# Accessibility (WCAG 2.2 AA)

Target: **WCAG 2.2 Level AA**. Legally enforced in the EU (European Accessibility Act) and US
(ADA Title II). Treat these as build-time requirements, not polish.

The complete catalogue — 38+ anti-patterns with IDs, framework-specific fixes for Angular/Vue,
keyboard interaction tables, contrast tables, and the POUR audit checklist — is in
[`docs/reference/a11y-anti-patterns.md`](../docs/reference/a11y-anti-patterns.md). Read it when
auditing or remediating. The rules below apply to every component you write.

## Non-negotiable

- **Semantic HTML first.** A `<button>` before a `<div onClick>`; `<nav>/<main>/<header>` before
  `role="navigation"`. ARIA is a fallback for what HTML cannot express, never a substitute.
- **Every interactive element is keyboard-reachable and keyboard-operable.** If you add `onClick` to
  a non-native element you must also add `role`, `tabIndex={0}`, and `onKeyDown` for Enter/Space —
  or, better, use the native element instead.
- **Never `outline: none`** without an equally visible replacement focus indicator.
- **Never a positive `tabIndex`.** Use `0` or `-1` only; fix order via DOM order.
- **Icon-only buttons require an accessible name** — `aria-label` or visually-hidden text.
- **Every input has a real `<label htmlFor>`.** A placeholder is not a label.
- **Errors are linked to their input** via `aria-describedby` + `aria-invalid`, and are never
  signalled by colour alone.
- **Images**: informative → meaningful `alt`; decorative → `alt=""`. Never omit the attribute.
- **Contrast**: 4.5:1 body text, 3:1 for large text (18.66px+ bold / 24px+) and UI/graphic boundaries.
- **Respect `prefers-reduced-motion`** for any non-essential animation.

## React-specific

- **Route changes must move focus** — an SPA navigation that leaves focus on the old element strands
  screen-reader and keyboard users. Focus the new view's heading (`tabIndex={-1}` + `.focus()`).
- **Modals/dialogs**: trap focus while open, close on `Escape`, and return focus to the trigger on
  close. Prefer a primitive that does this for you over hand-rolling it.
- **Dynamic content** that appears without user action (toasts, async results, validation summaries)
  needs a live region — `aria-live="polite"`, or `assertive` only for genuinely urgent messages.
- **`aria-hidden="true"` must never wrap a focusable element** — it hides it from assistive tech
  while leaving it in the tab order.

## shadcn/ui primitives

shadcn/ui components are built on a headless primitive library — **historically Radix UI
(`@radix-ui/*`), and Base UI (`@base-ui/react`) in newer styles**. Check `package.json` to see which
this project actually uses before reasoning about a component's internals; the guidance below holds
for both, but the APIs and prop names do not.

Either way, the primitives already implement focus trapping, roving tabindex, escape handling, and
correct ARIA wiring. Two consequences:

- **Do not re-implement those behaviours** or add ARIA attributes the primitive already manages —
  duplicated `role`/`aria-*` is a common source of regressions.
- **Accessibility is preserved, not granted.** Verify what you compose on top: an accessible name on
  every trigger, a real `<label>` on every form field, and correct heading structure inside a
  `Dialog`.

## Verification

- Keyboard-only pass: Tab through the feature; nothing unreachable, nothing trapped, focus always
  visible.
- Check heading order (single `<h1>`, no skipped levels) and that landmarks wrap all content.
- Zoom to 200% and narrow to 320px — content must reflow without horizontal scrolling.
